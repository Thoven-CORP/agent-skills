# Delivery and freshness

## One document, one reading tab

Keep the canonical file path stable while revising the same artifact. Open a new completed artifact once in Dia. For updates, locate the known tab through an available browser controller and refresh that tab after saving. Report the stable path and what changed in chat.

When tab control is unavailable, save the update and say that the existing tab needs refresh. A shell `open` call is not proof of tab reuse. Avoid another open or a new cache-busting URL for each revision. Preserve the reader's place and workbook answers when the available controls allow it; describe any limit honestly.

## Freshness belongs beside the content

Show a simple updated date and source context when useful. Label stale media and distinguish email previews from actual delivery where the difference affects the reader. Reuse existing evidence metadata; do not create a new receipt for every item. Editing prose does not refresh embedded evidence.

Keep claims within the evidence already available and link technical records when useful. Packaging those records does not trigger another QA run.

## Optional live view — proposed capability, not shipped support

The current finisher produces a static file. Workbook autosave preserves answers; it does not refresh source content. No verified Dia tab-reuse or live-update helper ships with this skill.

For a waiting-heavy task, propose one stable live URL backed by a controlled session on the Mac mini, while retaining a self-contained snapshot for sharing. The live view should show last successful update, pending work and any refresh failure; changes should arrive in place while preserving scroll, answers and video playback. Pause/resume updates should be visible.

Live-update tooling is separate future work, not a prerequisite for an internal document. Until supported tooling exists, deliver the stable static file. Do not start a helper build or capability-probe run just to deliver an artifact.
