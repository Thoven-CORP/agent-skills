# Focused review

Use when Andres names a skill to reflect on. Resolve its actual path and window before mining. Read its purpose, current `SKILL.md` instructions and `LEARNINGS.md` if present. An explicit date range wins; otherwise use the last seven days, independent of the global weekly checkpoint. Treat a date-only end as inclusive in the user's local timezone. Report the resolved range and target. This is native free text, not a new miner flag.

Use the existing miner with `--since` and a unique per-run output directory. The miner still scans the selected harness/date window; the focused digest narrows reviewer context, not necessarily mining I/O. Include relevant corrections in sessions that actually loaded the target and relevant cases where it should have fired or a task exposed its capability gap, even if it did not load. `skills.tsv` and last-loaded skill are leads, not proof that the target caused an outcome; inspect nearby transcript context to establish attribution.

Bound positive and discovery leads by searching `prompts.tsv` for target and task-relevant terms, then inspect only nearby raw human turns. The prompts index has no event timestamps: validate each lead's actual human authorship, event timestamp and relevance in the raw transcript; exclude relays, pasted material and out-of-window events. An agent's claim of success is not a user's endorsement or observed quality. Include useful successes and discoveries to preserve or investigate, without turning every observation into a rule. Label unvalidated leads unverified and do not count them as evidence.

The miner has no `--until`: for an explicit end, filter every candidate at its event timestamp against the full resolved range, including corrections and validated positive leads; session file dates and aggregate skill counts are not event dates. The miner deduplicates corrections across sessions, so a focused digest may omit repeated or later instances; inspect relevant raw turns where necessary to establish distinct-session recurrence, and report any coverage limit. Do not infer zero cases from an incomplete scan.

Write validated relevant evidence and its raw source pointers into `<out>/focused.md`; retain rejected and unverified leads separately from counted evidence. Pass the target, resolved window, focused digest and limitations to every reviewer and the synthesizer. Review only evidence relevant to this focus; dispatch aggregates without event-level attribution to the target and window are context, not findings. Refer a supported issue owned elsewhere without expanding the edit scope. If there are no supported findings, report that outcome without forcing proposals.
