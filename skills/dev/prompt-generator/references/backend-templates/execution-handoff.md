# Execution Handoff Template

Use for: handing off a generated prompt to an executing agent or session.

This template wraps a generated prompt with execution context so the implementer
has everything they need to start coding without additional research.

## Template Structure

```
## Execution Handoff: [Task Name]

### Pre-Read (REQUIRED before coding)
Read these files to understand context:
1. [file path] — [why]
2. [file path] — [why]
3. [file path] — [why]

### Pattern Files (follow these conventions)
- Controller pattern: [path]
- Service pattern: [path]
- Spec pattern: [path]
- Factory pattern: [path]
- Migration pattern: [path]

### The Prompt
[Full prompt generated by prompt-generator]

### Implementation Order
1. [ ] Migration (if needed) — run in both environments
2. [ ] Model (associations, validations, scopes, callbacks)
3. [ ] Service (business logic with transaction boundaries)
4. [ ] Serializer (JSONAPI::Serializer response shape)
5. [ ] Controller (thin — delegates to service)
6. [ ] Routes (namespace under api/v1)
7. [ ] Specs (model → service → request)
8. [ ] Manual verification (rails console + curl)

### Gotchas for This Codebase
- UUIDs everywhere — use `id: :uuid` in migrations, `type: :uuid` in references
- Dual auth — User vs Student Devise models are SEPARATE
- Profile types are integers (1=Admin, 2=Parent, 3=Teacher) — use helpers like `profile.teacher?`
- Soft deletes — add `archived_at` column, filter with `where(archived_at: nil)`
- Production data has nils — always use safe navigation (`&.`) and defaults
- Commit workflow: `git add -A && git commit` — ask about Publication Status

### Verification Checklist
- [ ] bundle exec rspec (full suite passes)
- [ ] New specs cover happy path + error cases + auth
- [ ] No N+1 queries (check includes in controller)
- [ ] Error responses match existing format
- [ ] Migration runs in both environments
```

## Example Usage

After generating an implementation prompt for "add student practice logging":

```
## Execution Handoff: Student Practice Logging

### Pre-Read
1. app/models/student.rb — existing student model, associations
2. app/controllers/api/v1/students/ — student-namespaced controller pattern
3. .claude/docs/ARCHITECTURE.md — schema context, existing tables
4. .claude/docs/COMMON_ERRORS.md — known pitfalls to avoid

### Pattern Files
- Controller: app/controllers/api/v1/parents/bookings_controller.rb
- Service: app/services/booking_request_service.rb
- Serializer: app/serializers/booking_serializer.rb
- Spec: spec/requests/api/v1/esa_leads_spec.rb
- Factory: spec/factories/bookings.rb
- Migration: db/migrate/20260310152511_create_esa_leads.rb

### The Prompt
[Generated implementation prompt goes here]

### Implementation Order
1. [ ] Migration: create_practice_sessions table
2. [ ] Model: PracticeSession with validations and Student association
3. [ ] Serializer: PracticeSessionSerializer
4. [ ] Service: PracticeSessionService (create with validation)
5. [ ] Controller: Api::V1::Students::PracticeSessionsController
6. [ ] Routes: resources :practice_sessions under students namespace
7. [ ] Specs: model → service → request
8. [ ] Manual: rails console test + curl endpoints
```
